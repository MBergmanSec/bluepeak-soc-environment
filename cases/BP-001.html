BP-001

Suspicious PowerShell Execution

Finance workstation investigation using Sysmon, Windows Security, and PowerShell telemetry in Splunk.

HIGHLY SUSPICIOUS
SeverityMedium
HostBNE-FIN-WS01
DepartmentFinance
DispositionEscalated
ContainmentIsolation Recommended

SUMMARY

Executive summary

BNE-FIN-WS01 executed unusual PowerShell activity under the LocalAdmin account. A hidden PowerShell process created a file in the user's Temp directory. PowerShell subsequently performed a DNS query to example.com, followed by cmd.exe executing whoami, with output written to an additional Temp file. No associated outbound network connection was confirmed. Escalation and host isolation were recommended.

ANALYSIS

Analyst Reasoning

The initial PowerShell command line raised suspicion due to the use of -ExecutionPolicy Bypass and -NoProfile in the context of unusual activity on a Finance workstation.

Investigation of the subsequent Sysmon Event ID 11 confirmed that PowerShell created a file within the user's Temp directory, increasing my suspicion. Further DNS activity and user discovery added to the suspicious execution chain.

Although I could not confirm a successful outbound network connection, the combined behaviour lacked an identified legitimate business explanation and was sufficient for me to recommend isolation of the workstation.

MITRE ATT&CK

Technique Mapping

T1059.001 — PowerShell

Confirmed PowerShell execution was observed during the investigation, including execution using -NoProfile and -ExecutionPolicy Bypass.

T1087 — Account Discovery

Process telemetry confirmed execution of whoami.exe to identify the account associated with the current security context.

T1105 — Ingress Tool Transfer

Suspected / not confirmed. File creation occurred alongside DNS and attempted web-related activity, but the available telemetry did not confirm that the file was transferred from an external system.

RETROSPECTIVE

Lessons Learned

Looking back, I could have followed the file activity more thoroughly after confirming the Temp file creation, particularly by investigating what interacted with the file afterward.

I also initially put too much weight on the DNS and web activity and had to separate what the telemetry actually proved from what I suspected had occurred. DNS resolution and file creation did not prove that a successful download or outbound connection had taken place.

The investigation also identified a monitoring gap: successful Windows logon auditing was not enabled during the incident, meaning authentication activity could not be retrospectively validated. This was corrected after the investigation and Event ID 4624 ingestion into Splunk was validated.

In future investigations I would build the timeline more systematically and follow each process, file, network and authentication pivot before forming a final conclusion.
